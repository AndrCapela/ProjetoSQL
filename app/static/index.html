Guia Técnico de SQL (SQLite • DuckDB Friendly SQL • Keywords & Dialetos)

        

        

          
          
        

      

      

        
        
        
        
      

      

        

          

            Ambiente SQLite Somente Leitura: consultas devem iniciar com SELECT ou WITH (CTE).
            Datas estão armazenadas como texto ISO (YYYY-MM-DD) e divisão entre inteiros é truncada (use * 1.0 para decimal).
          

          

            

              
1. Ordem Lógica de Execução & Escopo de Aliases

              
A ordem em que o motor processa a query explica por que aliases do SELECT não existem no WHERE, mas funcionam no ORDER BY:

              
    
                
  1. FROM / JOIN ... ON — monta o conjunto cartesiano e aplica junções
    2. 
                
  2. WHERE — filtra linhas individuais antes de agrupar
    3. 
                
  3. GROUP BY — consolida linhas por chave de agrupamento
    4. 
                
  4. HAVING — filtra grupos (aceita COUNT, AVG, SUM...)
    5. 
                
  5. SELECT / DISTINCT — projeta expressões e define aliases
    6. 
                
  6. WINDOW (OVER (...)) — calcula funções analíticas sobre o resultado
    7. 
                
  7. ORDER BY → LIMIT / OFFSET — ordena e recorta linhas finais
    8. 
              

            

            

              
2. Filtros, Conjuntos & Tratamento de NULL

              
No SQL, NULL representa valor desconhecido: col = NULL nunca é verdadeiro — use sempre IS NULL ou IS NOT NULL.

              

                
                
SELECT nome, idade, cidade
FROM alunos
WHERE cidade IN ('Curitiba', 'Porto Alegre')
  AND idade BETWEEN 20 AND 35
  AND nome LIKE '%Silva%'
  AND email IS NOT NULL;

              

            

            

              
3. JOINs, Anti-Join (LEFT + IS NULL) & N:N

              
Use INNER JOIN para interseção, LEFT JOIN para preservar a tabela à esquerda e WHERE direita.id IS NULL (ou NOT EXISTS) para achar registros sem correspondência:

              

                
                
-- Alunos sem nenhuma matrícula
SELECT a.id, a.nome, a.email
FROM alunos a
LEFT JOIN alunos_disciplinas ad ON ad.aluno_id = a.id
WHERE ad.id IS NULL;

              

            

            

              
4. Agregação, HAVING & Agregação Condicional

              
Toda coluna no SELECT fora de agregação precisa estar no GROUP BY. Para proporções no SQLite, multiplique por 100.0 antes de dividir:

              

                
                
SELECT
    d.nome AS disciplina,
    COUNT(ad.id) AS inscritos,
    ROUND(
        SUM(CASE WHEN ad.status = 'concluida' THEN 1 ELSE 0 END) * 100.0
        / COUNT(ad.id),
        2
    ) AS taxa_conclusao_pct
FROM disciplinas d
INNER JOIN alunos_disciplinas ad ON ad.disciplina_id = d.id
GROUP BY d.id, d.nome
HAVING COUNT(ad.id) >= 3;

              

            

            

              
5. CTE (WITH) & Window Functions

              
Window functions preservam todas as linhas (não colapsam como GROUP BY). No SQLite, envolva em CTE/subquery para filtrar por posição de ranking:

              

                
                
WITH ranking AS (
    SELECT
        d.nome AS disciplina,
        a.nome AS aluno,
        n.nota,
        RANK() OVER (PARTITION BY d.id ORDER BY n.nota DESC) AS pos
    FROM notas n
    JOIN alunos_disciplinas ad ON ad.id = n.aluno_disciplina_id
    JOIN alunos a ON a.id = ad.aluno_id
    JOIN disciplinas d ON d.id = ad.disciplina_id
)
SELECT disciplina, aluno, nota
FROM ranking
WHERE pos = 1
ORDER BY disciplina ASC, aluno ASC;

              

            

            

              
6. Datas, Subqueries & Funções Úteis no SQLite

              
Extração de data com strftime, fallback de nulos com COALESCE e comparação com subquery escalar:

              

                
                
SELECT
    a.nome,
    strftime('%Y', a.data_matricula) AS ano_ingresso,
    ROUND(AVG(n.nota), 2) AS media
FROM alunos a
JOIN alunos_disciplinas ad ON ad.aluno_id = a.id
JOIN notas n ON n.aluno_disciplina_id = ad.id
WHERE strftime('%Y', a.data_matricula) = '2024'
GROUP BY a.id, a.nome, a.data_matricula
HAVING AVG(n.nota) > (SELECT AVG(nota) FROM notas);

              

            

          

        


        

          

            Importante — SELECT e WITH continuam 100% válidos: no DuckDB você não precisa começar queries com FROM.
            Você pode escrever SQL tradicional (SELECT ... FROM ...) e usar livremente os recursos de Friendly SQL dentro dele — o FROM no início (FROM-first) é apenas um atalho opcional.
          

          

            

              
1. Formas Válidas de Iniciar uma Query

              
Todas as variações abaixo são válidas no DuckDB e produzem o mesmo plano de execução:

              

                
                
-- 1) Padrão SQL tradicional (recomendado e universal)
SELECT nome, idade FROM alunos WHERE idade > 30;

-- 2) FROM-first opcional (útil em exploração)
FROM alunos SELECT nome, idade WHERE idade > 30;

-- 3) SELECT * implícito e inspeção rápida (Modo Livre)
FROM alunos LIMIT 10;
SUMMARIZE alunos;
DESCRIBE alunos;

              

            

            

              
2. GROUP BY ALL, ORDER BY ALL & Alias no HAVING

              
Funciona normalmente com queries iniciadas por SELECT. GROUP BY ALL infere todas as colunas não agregadas do SELECT, e o HAVING aceita aliases definidos no SELECT:

              

                
                
SELECT
    p.nome AS professor,
    COUNT(d.id) AS total_disciplinas
FROM professores p
INNER JOIN disciplinas d ON d.professor_id = p.id
GROUP BY ALL
HAVING total_disciplinas >= 2
ORDER BY total_disciplinas DESC, professor ASC;

              

            

            

              
3. QUALIFY & Cláusula WINDOW Nomeada

              
QUALIFY filtra o resultado de window functions sem precisar de CTE/subquery. Regra do DuckDB 2.x: quando combinar QUALIFY com GROUP BY, liste as colunas explicitamente no GROUP BY (em vez de GROUP BY ALL):

              

                
                
SELECT
    a.nome,
    COUNT(ad.id) AS total_disciplinas,
    DENSE_RANK() OVER (ORDER BY COUNT(ad.id) DESC) AS ranking
FROM alunos a
INNER JOIN alunos_disciplinas ad ON ad.aluno_id = a.id
GROUP BY a.id, a.nome
QUALIFY ranking <= 2
ORDER BY ranking ASC, a.nome ASC;

              

            

            

              
4. COUNT_IF, BOOL_AND & Aliases Laterais

              
Substitua SUM(CASE WHEN ...) por COUNT_IF(...) ou FILTER (WHERE ...), verifique condição universal com BOOL_AND(...) e reutilize aliases calculados no mesmo SELECT:

              

                
                
SELECT
    d.nome AS disciplina,
    COUNT(ad.id) AS inscritos,
    ROUND(COUNT_IF(ad.status = 'concluida') * 100.0 / inscritos, 2) AS taxa_pct
FROM disciplinas d
JOIN alunos_disciplinas ad ON ad.disciplina_id = d.id
GROUP BY ALL
ORDER BY taxa_pct DESC;

-- Alunos com 100% das matrículas concluídas:
SELECT a.id, a.nome, COUNT(ad.id) AS total
FROM alunos a
JOIN alunos_disciplinas ad ON ad.aluno_id = a.id
GROUP BY ALL
HAVING BOOL_AND(ad.status = 'concluida');

              

            

            

              
5. ANTI JOIN, SEMI JOIN & PIVOT Nativo

              
ANTI JOIN retorna linhas da esquerda sem correspondência à direita; SEMI JOIN retorna linhas com pelo menos 1 correspondência sem duplicar registros; PIVOT transforma valores em colunas:

              

                
                
-- Cursos sem disciplinas (também funciona com SELECT ... FROM ... ANTI JOIN ...)
SELECT c.id, c.nome, c.categoria
FROM cursos c
ANTI JOIN disciplinas d ON d.curso_id = c.id;

-- Matriz de status de matrículas
PIVOT (SELECT status FROM alunos_disciplinas)
ON status IN ('cursando', 'concluida', 'trancada')
USING COUNT(*);

              

            

            

              
6. Datas (DATE), ILIKE, EXCLUDE / REPLACE & Divisão

              
No DuckDB, colunas de data são DATE, / entre inteiros retorna decimal (5 / 2 = 2.5; use 5 // 2 para divisão inteira) e strftime recebe a data antes do formato:

              

                
                
SELECT nome, cidade, data_matricula
FROM alunos
WHERE YEAR(data_matricula) = 2025
  AND data_matricula >= DATE '2025-02-01'
  AND cidade ILIKE '%são paulo%';

-- Projeção dinâmica excluindo ou transformando colunas:
SELECT * EXCLUDE (email, data_contratacao) REPLACE (ROUND(salario, 0) AS salario)
FROM professores;

              

            

          

        


        

          

            Referência técnica das principais palavras-chave, operadores, funções e armadilhas comuns avaliadas nos exercícios e no Modo Livre.
          


          
1. Cláusulas Estruturais

          

            

              
                

                  Keyword
                  Motor
                  Função Técnica
                  Exemplo
                

              
              
                

                  SELECT / DISTINCT
                  SQLite + DuckDB
                  Projeta colunas/expressões calculadas; DISTINCT elimina duplicatas do resultado.
                  SELECT DISTINCT cidade FROM alunos;
                

                

                  FROM (padrão ou FROM-first)
                  SQLite + DuckDB
                  Define a fonte de dados. No DuckDB, pode opcionalmente abrir a query antes do SELECT.
                  SELECT nome FROM alunos; / FROM alunos SELECT nome;
                

                

                  INNER / LEFT JOIN
                  SQLite + DuckDB
                  INNER exige match nos dois lados; LEFT preserva todas as linhas da tabela à esquerda.
                  FROM alunos a LEFT JOIN alunos_disciplinas ad ON ad.aluno_id = a.id
                

                

                  ANTI JOIN / SEMI JOIN
                  DuckDB
                  Atalho para NOT EXISTS (sem correspondência) e EXISTS (com correspondência sem duplicar).
                  SELECT c.nome FROM cursos c ANTI JOIN disciplinas d ON d.curso_id = c.id;
                

                

                  WHERE
                  SQLite + DuckDB
                  Filtra linhas antes do agrupamento. Não aceita agregações (AVG, COUNT) nem window functions.
                  WHERE idade BETWEEN 25 AND 30 AND cidade != 'Recife'
                

                

                  GROUP BY / GROUP BY ALL
                  SQLite + DuckDB
                  Agrupa linhas por chave. GROUP BY ALL (DuckDB) deduz automaticamente todas as colunas não agregadas do SELECT.
                  SELECT cidade, COUNT(*) FROM alunos GROUP BY ALL;
                

                

                  HAVING
                  SQLite + DuckDB
                  Filtra grupos após o GROUP BY com base em funções agregadas. No DuckDB, aceita aliases do SELECT.
                  HAVING COUNT(d.id) >= 2 AND AVG(n.nota) >= 8.0
                

                

                  WINDOW / OVER
                  SQLite + DuckDB
                  Define janelas de partição e ordenação para cálculos analíticos sem colapsar linhas.
                  AVG(nota) OVER (PARTITION BY d.id) ou WINDOW w AS (PARTITION BY d.id)
                

                

                  QUALIFY
                  DuckDB
                  Filtra o resultado de window functions diretamente na query, dispensando CTE/subquery.
                  SELECT ..., RANK() OVER (...) AS r FROM ... QUALIFY r = 1;
                

                

                  ORDER BY / ORDER BY ALL
                  SQLite + DuckDB
                  Ordena resultados (ASC padrão, DESC decrescente). ORDER BY ALL (DuckDB) ordena por todas as colunas projetadas.
                  ORDER BY nota DESC, nome ASC
                

                

                  LIMIT / OFFSET
                  SQLite + DuckDB
                  Restringe a quantidade máxima de linhas retornadas e permite pular linhas iniciais.
                  LIMIT 10 OFFSET 0
                

                

                  WITH (CTE)
                  SQLite + DuckDB
                  Define consultas nomeadas temporárias para organizar cálculos em etapas e subqueries reutilizáveis.
                  WITH medias AS (SELECT ...) SELECT * FROM medias;
                

                

                  UNION / UNION ALL
                  SQLite + DuckDB
                  Empilha resultados de consultas com mesmo número de colunas. UNION remove duplicatas; UNION ALL mantém tudo (mais rápido).
                  SELECT nome FROM alunos UNION ALL SELECT nome FROM professores;
                

                

                  PIVOT / EXCLUDE / SUMMARIZE
                  DuckDB
                  PIVOT transforma categorias em colunas; * EXCLUDE (c) omite colunas; SUMMARIZE perfila a tabela (Modo Livre).
                  SELECT * EXCLUDE (email) FROM alunos;
                

              
            

          


          
2. Operadores & Funções Essenciais

          

            

              
                

                  Categoria
                  Símbolos / Funções
                  Comportamento e Observações
                

              
              
                

                  Comparação & Lógicos
                  =, != / <>, <, <=, >, >=, AND, OR, NOT
                  AND tem precedência maior que OR: sempre use parênteses ao misturar os dois (WHERE (a = 1 OR b = 2) AND c = 3).
                

                

                  Faixas, Listas & Padrões
                  BETWEEN a AND b, IN (...), LIKE, ILIKE, IS NULL
                  BETWEEN é inclusivo nos dois extremos. Em padrões, % casa 0+ caracteres e _ casa exatamente 1 caractere.
                

                

                  Subqueries & Condicional
                  EXISTS (...), NOT EXISTS (...), CASE WHEN ... THEN ... ELSE ... END
                  NOT EXISTS é imune a NULL na subquery (ao contrário de NOT IN quando há NULL retornado).
                

                

                  Agregação
                  COUNT(*), COUNT(col), COUNT(DISTINCT col), SUM, AVG, MIN, MAX, COUNT_IF, BOOL_AND
                  COUNT(*) conta todas as linhas; COUNT(col) e AVG(col) ignoram NULL. COUNT_IF e BOOL_AND são nativos do DuckDB.
                

                

                  Window Functions
                  RANK(), DENSE_RANK(), ROW_NUMBER(), LAG(), LEAD(), AVG() OVER (...)
                  Em empates [10, 10, 9]: ROW_NUMBER gera 1,2,3; RANK gera 1,1,3; DENSE_RANK gera 1,1,2.
                

                

                  Texto, Datas & Conversão
                  ROUND(x, 2), COALESCE(a, b), LOWER/UPPER, CAST(x AS ...), strftime, YEAR()
                  No SQLite: strftime('%Y', col). No DuckDB: YEAR(col) ou strftime(col, '%Y'); cast curto com col::DATE.
                

              
            

          


          
3. Armadilhas Comuns (Resumo Rápido)

          

            

              
WHERE vs HAVING vs QUALIFY

              
WHERE filtra linhas cruas antes de agrupar; HAVING filtra grupos criados pelo GROUP BY; QUALIFY (DuckDB) filtra resultados de funções de janela (RANK(), AVG() OVER).

            

            

              
COUNT(*) vs COUNT(col) em LEFT JOIN

              
Em um LEFT JOIN, usar COUNT(*) conta a linha do lado esquerdo como 1 mesmo quando não há match à direita. Use sempre COUNT(tabela_direita.id) para contar apenas correspondências reais.
